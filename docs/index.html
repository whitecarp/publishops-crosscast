一句话，发往你选的所有平台。

把视频交给你正在用的 AI 助手（如 Codex、Claude）：它为 B站、YouTube、抖音、Instagram 和 X 各写一版标题和简介，vpub 适配封面，首次登录之后在后台逐个平台提交，读回到作品才算发布。发完之后，改稿、回评论、看数据也能接着交给它。

开始之前

  • 用能运行本机命令的 AI 助手，如 Codex 或 Claude Code；只有聊天功能的窗口不够。
  • 在中国大陆使用 YouTube、Instagram 或 X，需要自己想办法哦。
  • X 需要订阅，而且账号确实能进入 Media Studio；仅付费不保证可用。

不熟悉电脑？复制完整的新手提示词，含首次预览和安全反馈步骤。

对你的 AI 助手说

帮我从 https://github.com/whitecarp/publishops-crosscast 安装 PublishOps CrossCast，运行 vpub doctor 并读取它给出的 skill 文件。然后把 final.mp4 公开发布到[我选择的平台]，封面用 cover.jpg，标题和简介按平台来写，每个平台首次发布都先给我看当前方案并等我明确同意；确认码不代表同意。这条视频是中文的，（有/没有）用 AI 制作，讲的是：（用一句话说说）

把文件名和内容换成你的；平台和公开范围可以按需修改。

你说一句，AI 助手去办

文字由你正在用的 AI 助手来写，不内置模型，也不用另配模型 API Key；vpub 负责方案、封面适配、预演和回执。

你可以这样说它会做什么它不会

  • 你可以这样说：把这条视频发 B站和 YouTube，标题口语一点。

    它会做什么按平台各写一版标题、简介和标签，直接提交到这两个平台，并记录每一步的回执。

    它不会因为某个平台已登录就顺手加上，或者擅自改动公开范围。

  • 你可以这样说：封面按各平台尺寸适配一下，原图别动。

    它会做什么按平台画布另存一份封面，保留完整画面。发抖音或 Instagram 还需要一张竖版封面：AI 助手能画就画一张，不能画就用 vpub covers portrait 从原图挑内容重新排版。平台预览仍可能裁切，提交前请看一眼。

    它不会裁切、拉伸或覆盖你的原图。

  • 你可以这样说：这条中文视频也发 YouTube，让外国观众看得懂。

    它会做什么文案跟着视频语言走：B站、抖音用简体中文，YouTube、Instagram、X 用英文；视频本身是别的语言时，先保留原文，再附上平台语言的译文。所以这条在 YouTube 上是中文在前、英文在后。

    它不会翻译视频里的配音或字幕。

  • 你可以这样说：上次那条到底发出去没有？

    它会做什么查本地回执，按平台告诉你到了哪一步；能读回的，再到平台上核对。

    它不会把排队、登录链接或本地回执说成“已发布”。

每个状态，都叫它本来的名字

直接发布，也要说清楚到了哪一步。AI 助手按实际证据汇报，不会把前一步说成后一步。

  1. 排队中

    任务已记录，还没开始上传。

  2. 发布中

    CLI 正在后台上传和提交。

  3. 已提交，待核验

    平台已接收提交，可能还在审核或处理中，还没有读回到作品。

  4. 已核验

    已从平台页面或 API 读回到这条作品。审核和公开状态以平台显示为准。

  • 遇到验证、风控或限流：所有平台都停下。你在官方页面处理好、查明原因后，用 vpub stop --clear 解除。
  • 结果不明：只核对原来的任务，不重复上传。

默认开着的安全限制

  • 回复、私信和点赞有上限：每日上限，不对同一个人重复相同的话，标注 AI。
  • 回复和私信不发密钥和未经同意的链接：标题和简介也会检查，像密码或密钥的内容会被拒绝，链接只会提醒你看一眼。
  • 可疑的消息留给你：试图诱导助手的消息，或需要真人处理的消息，要有人批准才能回复。被骗的助手仍可能自己批准，关键词检查也不是绝对保证。
  • 随时能查还有什么没做完：vpub status 只读本地记录，列出没做完的事和下一步的确切命令。

三步，从安装到第一次发布

  1. 安装

    需要 Python 3.10–3.14 和 Google Chrome。把上面那段话交给 AI 助手，或者自己运行：

    python -m pip install https://github.com/whitecarp/publishops-crosscast/archive/refs/heads/main.zip

    Windows 也可以用仓库里的 install.ps1；macOS 和 Linux 尚未验收。

  2. 检查环境

    查看本机依赖和实际可用的发布路径。这两条命令都不会登录或发布。

    vpub doctor
    vpub capabilities

  3. 说一句，直接发布

    告诉 AI 助手视频文件、要发的平台和公开范围，它就逐个平台提交并记录回执。第一次登录各平台时，扫码和验证码由你完成；平台可能把 CrossCast 的专用浏览器当成新设备，要求你验证身份，也由你在官方页面完成。之后 CLI 在后台复用登录。

想自己动手？看手动流程 
vpub init --video final.mp4 --language zh-Hans --out publish.json --platforms bilibili,douyin,youtube
vpub metadata request publish.json --source script.txt --out request.json
vpub metadata apply publish.json --request request.json --response response.json --out localized.json
vpub covers prepare localized.json --source cover.jpg --portrait portrait.jpg --out-dir covers --out ready.json
vpub plan ready.json
vpub publish ready.json --dry-run
vpub publish ready.json --confirm <confirmation-code>
vpub verify RECEIPT_KEY

--dry-run 不会上传。response.json 由 AI 助手按 request.json 里的模板撰写。vpub init 默认声明为 AI 生成内容，YouTube 默认私享，Instagram 和 X 跟随账号设置；普通视频加 --ai-generated no，要改公开范围就在 vpub init 之后马上改 publish.json 里的 visibility。 首次在每个平台发布或启用“每次先给我看”时，上面的发布命令会停下要求审核。展示当前方案并等用户明确同意后，才用它的当前确认码执行 vpub publish ready.json --confirm CODE --person-approved；go 也需要这两个独立参数。参数只是调用者声明，软件不能证明用户同意。

常见问题

没找到答案？可以到 GitHub 提问，提问前请先移除账号和私密信息。

发布前还要我再确认吗？

当前本地数据目录里，每个平台首次正式发布前，助手都要展示当前方案并停下来，等你说“发”。这按平台判断，不跟踪账号或频道是否首次使用。该平台后续按你的发布指令执行；保存了“每次先给我看”或临时要求预览时，每次都要等你同意。需要审核时，当前 --confirm CODE 必须与单独的 --person-approved 一起使用；确认码本身不代表同意，参数也只是调用者的声明，软件无法证明你真的说过“可以”。内容、账号、平台、受众或范围改变，仍需确认。偏好不等于长期发布授权。

需要单独的模型 API Key 吗？

不需要。CrossCast 不内置模型，标题和简介由你正在用的 AI 助手来写。只有付费的 YouTube API 路径才需要自行配置 Google OAuth 桌面客户端；免费路径由后台 Chrome 在 YouTube Studio 上发布。

它会帮我登录账号吗？

登录在官方页面完成，扫码、密码和验证码都由你本人操作。平台可能把 CrossCast 的专用浏览器当成新设备，要求验证或找回账号，同样由你本人在官方页面处理。不要在对话、日志或仓库里提供 Cookie、密码、验证码或令牌。这个页面也不收集任何信息。

只在终端里运行 vpub，能直接发出去吗？

能。首次登录之后，CLI 自己在后台完成上传，不需要 AI 助手一步步操作浏览器。登录过期或平台要求验证时，需要你回到官方页面处理。

进了队列或有了回执，就算发出去了吗？

不算。排队只说明任务已记录；本地回执记录每一步的证据，但它本身不代替平台证据。是否发布成功，以平台页面读回或平台 API 为准。

会改动我的原视频和封面吗？

不会。适配后的封面另存为新文件，原图保持不变；发 Instagram 时直接使用原视频，不转码。

会不会发到我没选的平台？

不会因为某个平台已登录就把它加进来。平台、账号和公开范围由你选定；内容、账号、平台、受众或任务范围有变化时，会重新请你确认。

要花钱吗？

CrossCast 核心开源免费（MIT），发布和日常运营都在里面。付费附加组件目前还没有开售，清单见上面的免费与付费，清单以外的功能都不需要它。你的 AI 助手订阅和 X 的订阅（发布要用 Media Studio）可能另有费用或限制，本项目不承诺免费或无限使用。

支持评论、私信和数据吗？TikTok 呢？

支持读评论并回复、点赞和收藏、查看 @ 提醒，在抖音、Instagram、X 上读发私信（B站还没实测），查看作品数据和巡检摘要；完整运营报告属于付费附加组件。各平台能做的不一样，见上面的能力表。每次只处理你授权的那一条，不会批量发送。TikTok 目前暂停支持。

现在能放心用于正式发布吗？

当前是 0.16.0 alpha。这一版已在 YouTube、抖音、Instagram 和 X 的真实账号上公开发布过，B站目前只有直接用旧版 bili-cli 的上传。登录会过期，平台也可能临时要求验证，长时间无人值守还没验收。第一次用时，可以先用预演（--dry-run）看一遍方案，再正式发布。
