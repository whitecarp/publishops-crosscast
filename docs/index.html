一句话，发往你选的所有平台。

你正在用的 AI 助手（如 Codex、Claude）为 B站、YouTube、抖音、Instagram 和 X 各写一版标题、简介和标签，vpub 生成并检查发布方案、按平台适配封面，首次登录之后在后台逐个平台提交，每一步都记录回执。不内置模型，也不需要另配模型 API Key。

对你的 AI 助手说

帮我从 https://github.com/whitecarp/publishops-crosscast 安装 PublishOps CrossCast，阅读 skills/publishops-crosscast/SKILL.md 并运行 vpub doctor。然后把 final.mp4 公开发布到 B站、YouTube、抖音、Instagram 和 X，标题和简介按平台来写。

把 final.mp4 换成你的视频文件；平台和公开范围可以按需修改。

你说一句，AI 助手去办

文字由你正在用的 AI 助手来写；vpub 负责方案、封面适配、预演和回执。

你可以这样说它会做什么它不会

  • 你可以这样说：把这条视频发 B站和 YouTube，标题口语一点。

    它会做什么按平台各写一版标题、简介和标签，直接提交到这两个平台，并记录每一步的回执。

    它不会因为某个平台已登录就顺手加上，或者擅自改动公开范围。

  • 你可以这样说：封面按各平台尺寸适配一下，原图别动。

    它会做什么按平台画布另存一份封面，保留完整画面。平台预览仍可能裁切，提交前请看一眼。

    它不会裁切、拉伸或覆盖你的原图。

  • 你可以这样说：B站和抖音用中文，YouTube 用英文。

    它会做什么按平台语言各写一版：B站、抖音用简体中文，YouTube、Instagram、X 用英文；要中英双语时说一声。

    它不会翻译视频里的配音或字幕。

  • 你可以这样说：上次那条到底发出去没有？

    它会做什么查本地回执，按平台告诉你到了哪一步；能读回的，再到平台上核对。

    它不会把排队、登录链接或本地回执说成“已发布”。

每个状态，都叫它本来的名字

直接发布，也要说清楚到了哪一步。AI 助手按实际证据汇报，不会把前一步说成后一步。

  1. 排队中

    任务已记录，还没开始上传。

  2. 发布中

    CLI 正在后台上传和提交。

  3. 已提交，待核验

    平台已接收提交，可能还在审核或处理中，还没有读回到作品。

  4. 已核验

    已从平台页面或 API 读回到这条作品。审核和公开状态以平台显示为准。

  • 遇到扫码、验证码或风控：停在原处，等你在官方页面处理。
  • 结果不明：只核对原来的任务，不重复上传。

五个平台，各走各的路

实测记录是过去的真实发布，不代表在你的账号、地区和平台状态下一定成功。本机实际能走哪条路径，以 vpub capabilities 的结果为准；B站是作者直接用 bili-cli 上传的，在那里仍标为未实测。

三步，从安装到第一次发布

  1. 安装

    需要 Python 3.10–3.12 和 Google Chrome。把上面那段话交给 AI 助手，或者自己运行：

    python -m pip install "git+https://github.com/whitecarp/publishops-crosscast.git"

    Windows 也可以用仓库里的 install.ps1；macOS 和 Linux 尚未验收。

  2. 检查环境

    查看本机依赖和实际可用的发布路径。这两条命令都不会登录或发布。

    vpub doctor
    vpub capabilities

  3. 说一句，直接发布

    告诉 AI 助手视频文件、要发的平台和公开范围，它就逐个平台提交并记录回执。第一次登录各平台时，扫码和验证码由你完成；之后 CLI 在后台复用登录。

想自己动手？看手动流程 
vpub init --video final.mp4 --language zh-Hans --out publish.json --platforms bilibili,douyin,youtube
vpub metadata request publish.json --source script.txt --out request.json
vpub metadata apply publish.json --request request.json --response response.json --out localized.json
vpub covers prepare localized.json --source cover.jpg --portrait portrait.jpg --out-dir covers --out ready.json
vpub plan ready.json
vpub publish ready.json --dry-run
vpub publish ready.json --confirm <confirmation-code>
vpub verify RECEIPT_KEY

--dry-run 不会上传。response.json 由 AI 助手按 request.json 里的模板撰写。

常见问题

没找到答案？可以到 GitHub 提问，提问前请先移除账号和私密信息。

发布前还要我再确认吗？

不用。你说要发布，就是授权：它按你说的平台、账号和公开范围直接提交。只有内容、账号、平台、受众或任务范围变了，它才会再问你。想先看一眼，就说“先别发”，或者用 --dry-run 预演。

需要单独的模型 API Key 吗？

不需要。CrossCast 不内置模型，标题和简介由你正在用的 AI 助手来写。只有用 CLI 发 YouTube 时，才需要自行配置 Google OAuth 桌面客户端；也可以让能操作浏览器的 AI 助手在 YouTube Studio 上发布。

它会帮我登录账号吗？

登录在官方页面完成，扫码、密码和验证码都由你本人操作。不要在对话、日志或仓库里提供 Cookie、密码、验证码或令牌。这个页面也不收集任何信息。

只在终端里运行 vpub，能直接发出去吗？

能。首次登录之后，CLI 自己在后台完成上传，不需要 AI 助手一步步操作浏览器。登录过期或平台要求验证时，需要你回到官方页面处理。

进了队列或有了回执，就算发出去了吗？

不算。排队只说明任务已记录；本地回执记录每一步的证据，但它本身不代替平台证据。是否发布成功，以平台页面读回或平台 API 为准。

会改动我的原视频和封面吗？

不会。适配后的封面另存为新文件，原图保持不变；发 Instagram 时直接使用原视频，不转码。

会不会发到我没选的平台？

不会因为某个平台已登录就把它加进来。平台、账号和公开范围由你选定；内容、账号、平台、受众或任务范围有变化时，会重新请你确认。

要花钱吗？

CrossCast 本身开源免费（MIT）。你的 AI 助手订阅、X 的订阅（发布要用 Media Studio），以及 YouTube API 的配额可能另有费用或限制，本项目不承诺免费或无限使用。

支持评论、私信和数据吗？TikTok 呢？

支持读评论并回复、点赞和收藏，在抖音、Instagram、X 上读发私信，查看作品数据和生成运营报告；各平台能做的不一样，每次只处理你授权的那一条，不会批量发送。TikTok 目前暂停支持。

现在能放心用于正式发布吗？

当前是 0.15.1 alpha。五个平台都有过真实发布或上传记录，但登录会过期，平台也可能临时要求验证，长时间无人值守还没验收。第一次用时，可以先用预演（--dry-run）看一遍方案，再正式发布。

开源免费，欢迎一起完善

MIT 许可。遇到问题或想支持新平台，欢迎到 GitHub 提 Issue；提交前请先移除账号和私密信息。
