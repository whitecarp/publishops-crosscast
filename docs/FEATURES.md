# 功能範圍

**繁體中文** · [English](FEATURES_EN.md)

**X 發布僅面向已訂閱、且帳號實際能進入 Media Studio 的使用者。**

原因是未訂閱帳號的影片上傳上限為 **140 秒、512 MB**，且無法使用本工具所依賴的 Media Studio 媒體管理與自訂封面流程。CrossCast 的 X 後端透過 Media Studio 上傳影片並設定製作封面，因此目前僅支援具備此權限的訂閱帳號。登入或付款本身不代表權限已開通，上傳前仍會核對媒體庫入口與所選帳號。[官方上傳限制](https://help.x.com/en/using-x/x-videos) · [Media Studio 權限](https://help.x.com/en/using-x/media-studio)。

**0.16.0 alpha。** 新方案在首次登入後由 CLI 執行；`method: native` 是明確選用的宿主瀏覽器備援。B站使用本套件內含的 [bili-cli](https://github.com/kukemc/bili-cli)，同時提供 `bili` 指令。

YouTube 欄中其他 API 項目同樣需要付費附加元件；`vpub capabilities` 會顯示本機實際可用的路徑。

共用能力：確切來源方案、逐平台帳號核對、不可變上傳快照、本機回執，以及最終提交後不盲目重試。瀏覽器 `works` 只讀可見首頁（抖音最多十張卡片）；尚無詳情 ID 的審核中作品保留待驗狀態。`vpub status` 列出未完成事項及每項的下一步指令，`vpub cleanup` 可釋放已完成影片副本佔用的磁碟空間。

第二期真實上傳及開發限制見[驗證記錄](VALIDATION.md)。背景瀏覽器不是官方直連 API，也沒有速度保證；介面變更、登入過期及驗證可能需要介入。文案寫作／翻譯由宿主聊天模型透過 request/apply 完成，不會翻譯影片本身。

內容語言與平台目標不同時保留原語言＋翻譯；中文的簡繁體在 B站／抖音統一簡體，不重複兩段。抖音自訂章節已接入 CLI 發布／驗證流程。`vpub edit` 支援 YouTube 資料、Instagram 配文、可用的 X 編輯入口及抖音封面／章節；native 交接仍保留。共用 v3 直圖已由使用者在兩站手機畫面確認底部文字可見；不能外推到所有手機版面。郵件僅支援 Gmail、預設關閉，使用者主動要求時才協助安裝／連接插件並開啟。Outlook、QQ、網易及 SMTP 均不支援。評論單語回覆與使用者語言匯報見 [README](OPERATIONS.md#評論作品數據與營運匯報)。TikTok、自動／批量私信及點讚、完整歷史匯出與 YouTube 卡片／可點擊片尾未實作。

當前限制以本頁表格及[最新驗證](VALIDATION.md)為準；以下版本記錄不是新的待辦清單。

## 0.16.0 — 付費 API 附加元件、內含 bili-cli、status 與 cleanup

X、Instagram 與 YouTube 的官方 API 路徑移至獨立的付費附加元件，其他路徑維持免費與 MIT 授權。YouTube 新增透過 Studio 的免費背景瀏覽器路徑。套件內含 bili-cli 1.2.1 及 `bili` 指令。新增 `vpub status`、`vpub cleanup`，`vpub messages sync` 也可讀取 B站 @ 提及與私信會話預覽。移除 `inbox`（改用 `messages`）、`--manage-playlists` 與 `--bilingual`。[升級說明](OPERATIONS.md#0160升級時的變化)。

## 0.15.0 — 恢復與完整讀取

合集操作復用一個瀏覽器環境。YouTube 上傳持久保存私密續傳會話；`read-all` 保存 API 游標並讀取支援的官方合集分頁。瀏覽器上傳與完整 DOM 歷史仍保留既有邊界。[指令](OPERATIONS.md#指令提速上傳恢復與完整讀取)。

## 0.14.0 — 合集成員與 Agent 技能

Instagram 收藏集更名與成員增刪、抖音作品合集管理、獨立讀回及具名 PublishOps CrossCast 技能。X 指定書籤夾成員變更與大型清單分頁仍待補齊。[指令](OPERATIONS.md#私人收藏集與平台差異)。

## 0.13.0 — 私人收藏集

X 私人書籤夾支援列出／建立／更名／刪除；Instagram 支援列出／建立／刪除及有界項目讀取，更名因讀回失敗停用。抖音僅核驗明確的空作品合集清單。具名成員變更與分頁仍待補；寫入使用持久 request ID、獨立讀回與明確的待核驗狀態。[用法](OPERATIONS.md#私人收藏集與平台差異)。

## 0.12.0 — 並行讀取、訊息續讀與播放列表

預設三個平台並行、同站共用連線／瀏覽器；獨立檢查點、合併鎖、stderr 進度。評論、提及與會話預覽共用快取及 `messages resume`。YouTube 新增 `playlist list/items/create/update/add/remove/move/delete/verify`，只管理本帳號的一般列表，單次提交並獨立讀回。[用法與限制](OPERATIONS.md#更快的巡檢與統一續讀)。

## 0.11.0 — 已有作品、增量巡檢與續讀

新增 `ops discover/adopt`，以有界目錄及重新核驗的歸屬接管手動發布作品；接管記錄與上傳回執分開。`ops sync` 支援 300 秒成功讀取復用、變更清單、逐步落盤及 `ops runs/run/resume`。API 保留分頁進度；未完成的瀏覽器作品重新讀取目前頁面，已完成項目不重讀。快取及部分覆蓋明確標示。0.11 當時未接入提及／私信續讀；0.12 已補齊。[用法與限制](OPERATIONS.md#已有作品接管與可恢復巡檢)。

## 0.10.0 — 提及通知與審核實測

抖音 @ 通知及 Instagram 標註／提及接入 `messages sync`，保留獨立基線及本機標記。抖音真實提及與去重已測；Instagram 僅入口及空列表完成實測。YouTube 觀眾頂層留言暫存／批准、X 他人回覆隱藏／恢復各完成一組讀回確認，均已恢復原狀態。支援明確的待核驗回執恢復，未知狀態不寫入。見[驗證記錄](VALIDATION.md)。

## 0.9.0 — 統一訊息巡檢

評論／提及／會話預覽共用本機清單與處理標記，來源獨立基線、瀏覽器有界補讀及明確的部分覆蓋狀態。X 提及及三平台私信預覽已實讀。YouTube 可讀審核隊列；觀眾評論暫存／批准與 X 隱藏／恢復仍屬實驗性，當時尚無合資格樣本；後續驗收見 0.10.0。見[指令與限制](OPERATIONS.md#統一訊息巡檢與評論補讀)。

## 0.8.0 — 抖音評論管理與單條私信

抖音新增評論點讚／取消讚及自己無回覆評論的刪除，保留確切 ID 綁定與獨立讀回。抖音／Instagram／X 新增 `dm list/read/send/verify`；X 另有使用者操作的 `dm unlock x`。B站私信與頂層評論置頂委派上游，本輪不做 B站實測。未驗證的隱藏／置頂明確拒絕，不用其他操作模擬。私信只用收件者語言；回執區分發送方可見與對方送達，待核驗不重送。見 [使用方式及限制](OPERATIONS.md#私信與平台差異)。

## 0.7.0 — 批次讀取與評論處理

唯讀瀏覽器批次減少重複啟動。本機評論歷史按帳號隔離，保留已處理／稍後處理標記，正文變更重新列為未讀。B站／YouTube 樓中樓補讀受樓層與頁數限制。新增 B站／Instagram／X 評論點讚及取消讚、YouTube 自己評論的編輯及刪除；寫入保留回執並重新讀回。以上為 0.7.0 範圍；0.8.0 已擴充抖音評論管理與私信，見上節。完整帳號收件匣仍未支援。[指令](OPERATIONS.md#管理單條評論)。

## 0.6.0 — 明確指定的點讚與收藏

五站共用 `engage status/like/save/verify`；`--remove` 撤銷對應操作。B站使用指定收藏夾、YouTube 使用自己擁有的普通播放列表、抖音與 Instagram 使用預設收藏、X 使用私人書籤。集合清單透過 `engage collections` 取得；後續已增加 `playlist` 與 `collection`，YouTube 稍後觀看仍未支援。

讀取當前狀態後提交一次，獨立讀回確認，重複的相同指令不產生新寫入。帳號變動、未知狀態及不唯一的控制項停止；待核驗操作不重送。中／英文匯報依回執列出已確認、撤銷和待核驗數，排除自測。安裝與巡檢不啟用自動互動。[用法與邊界](OPERATIONS.md#點讚收藏與撤銷)。

## 0.5.0 — 有界營運巡檢

五站作品列表；B站／YouTube 分頁與評論樓讀取；綁定帳號的追蹤清單；`ops sync` 彙整評論候選、可比較的數據變化及本輪匯報。只讀取，不建立排程或自動互動。[指令與限制](OPERATIONS.md#多平台巡檢與數據變化)。

## 0.2.0：跨平台內容設定

| 能力 | 本版範圍 |

| 文案生成 | 宿主模型 request/apply 與來源校驗；沒有獨立模型 API |

## 0.2.2：草稿與明確發布

Instagram／X 可用 `init --draft-only`，區分預覽與保存草稿；使用者明確改為發布後才用 `browser authorize-publish` 繼續同一份內容，不重傳。X 的草稿及原帖已實測，Instagram 首次提交失敗，重新登入及核對無重複後重試成功；封面網格裁切仍待適配。

## 0.2.3：刪除回執與封面限制

Instagram 新增明確刪除交接、確認結果與刷新後缺席證據、保留歷史的同片封面重發流程。已實測刪除；替換影片尚未分享。X 自訂封面改走需要訂閱權限的 Media Studio；本次媒體庫初始化失敗，封面修改未驗收。

## 0.2.4 歷史實驗：片頭方案已撤回

當時的 `instagram prepare` 自動判斷：橫式加入 1 秒原封面，直式／方形原片通過；維持原比例、原檔、可追溯雜湊及重跑復用。X 原橫式封面已透過 Studio 保存及發布；這是宿主網頁操作，不是新建了獨立 API。前面的 0.2.3 段落是歷史測試狀態，以最新 [驗證記錄](VALIDATION.md) 為準。

## 0.2.5：原影片與共用直式封面

依手機實測撤回一秒片頭處理，刪除該命令。Instagram 準備不改影片位元組、比例或時長；網頁另傳封面，手機從相機膠卷選抖音共用圖。交接回傳同一張圖片的路徑與雜湊，手機保存由使用者操作並驗收。
