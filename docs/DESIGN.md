# CrossCast 观众页设计说明

- **定位**：静态项目介绍页（GitHub Pages，`docs/`），不是发布控制台。没有登录、真实发布按钮或表单，不收集密钥，无外部 CDN、字体或遥测。
- **主张**：一句话，发往你选的所有平台。你说要发布就是授权，AI 助手逐个平台直接提交并记录回执；只有内容、账号、平台、受众或任务范围变化时才再问你。alpha 边界（登录会过期、平台可能临时要求验证、长时间无人值守未验收、TikTok 暂停）写在首屏和平台、FAQ 中。
- **概念：发布单**。首屏右侧是一张示意发布单：一条视频、五个去向，每行写清封面画布（取自 `covers.py` 预设）、文案语言（B站/抖音简中，YouTube/Instagram/X 英文）和真实状态。页面其余部分只有纸和墨，颜色只用来表示状态。
- **结构**：首屏（标题、说明、可复制的一句话、发布单）→ 怎么用（你可以这样说 / 它会做什么 / 它不会）→ 状态（排队中 → 发布中 → 已提交，待核验 → 已核验，以及“遇到扫码/验证码/风控”和“结果不明”两条规则）→ 平台范围表 → 三步上手 → 常见问题 → 结尾 → 页脚（独立工具声明）。
- **色彩**（`site.css` 的 `:root`）：纸 `#f4f6f9`、单据 `#ffffff`、墨 `#17213a`、次墨 `#4b566e` / `#5f6a83`、分隔线 `#d8dee8`。状态色：`idle` 灰（排队中）、`run` 蓝（发布中）、`pend` 琥珀（已提交待核验、alpha 提示）、`ok` 绿（已核验、可用）、`stop` 红（暂停）。平台小圆点只用于识别平台。深色模式跟随系统，是同一套 token 的反转（墨色桌面）。
- **状态印章**：颜色 + 边框样式 + 圆形图标的填充程度（虚线空心 → 四分之一 → 一半 → 实心），不只靠颜色区分。
- **字体**：只用系统字体，按 `:lang` 切换简体（PingFang SC / 微软雅黑 / Noto Sans CJK SC）、繁体（PingFang TC / 微软正黑体 / Noto Sans CJK TC）和英文字体栈；等宽字体只用于真实命令。
- **动效**：只有一处：首屏发布单逐行出现、印章落下。`prefers-reduced-motion` 时完全静止。
- **布局**：≥1121px 双栏，以下单栏。发布单是容器查询（`container: mf`），卡片宽度小于 500px 时自动改为每个平台两行，任何语言都不会叠字。平台表在 ≤760px 改为每个平台一块，用 ARIA role 保留表格语义。
- **多语言**：默认简体中文（HTML 本身就是简中，不启用脚本也完整）。`site.js` 内置繁體中文与 English 词典，覆盖正文、`aria-label`、标题和描述；`data-i18n-html` 只写入词典里的静态字符串。顶部“简 / 繁 / EN”同步 `aria-pressed`、`localStorage`（`crosscast-lang`）和 `?lang=` 参数；保存了非默认语言时，页面在切换完成前短暂隐藏，避免闪烁。繁体用语与 `README_ZH_TW.md` 一致（發布、帳號、影片）。
- **可访问性**：跳转链接、可见焦点环；复制结果用 `role=status` 播报，失败时自动选中文字；发布单与平台表为读屏提供隐藏标签；`forced-colors` 下印章保留边框。
- **分享图**：`docs/og.png`（1200×630）用于 `og:image` / `twitter:card`。GitHub 仓库的 Social preview 需要在仓库 Settings 里手动上传同一张图。
- **README 头图**：`assets/hero.svg`、`hero-zh-tw.svg`、`hero-en.svg` 与站点同一概念（左侧是你说的一句话，右侧是发布单），纯 SVG，系统字体回退栈，无脚本与外链。
- **维护**：改文案时同时改 `index.html`（简中）和 `site.js` 里的 TW、EN 词典；新增 `data-i18n` 键时三种语言都要有。示意内容（平台、状态、画布）要和当前 CLI 能力一致，不写观众版没有的功能。
